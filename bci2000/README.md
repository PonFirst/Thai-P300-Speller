# This project's BCI2000 modules (macOS)

| Module | What it is |
|---|---|
| `UnicornSerialSource` | Source module for the Unicorn Hybrid Black over its Bluetooth serial port. It stands in for BCI2000's `gUnicornADC`, which needs g.tec's Windows-only `Unicorn.dll`. It has the same parameters and the same nine per-sample states, plus gap filling. See `UnicornSerialSource/UnicornSerialADC.h`. |
| `CheckerboardSpeller` | Application module: the Thai 8×9 checkerboard speller. It is built on BCI2000's `StimulusTask`, like the stock P3Speller, with checkerboard groups reshuffled every repetition (a port of `collection/flash_sequence.py`). It has a cue before each character in copy mode and records each flash's group in the `.dat` file. See `CheckerboardSpeller/CheckerboardSpellerTask.h`. |
| `CheckerboardSignalProcessing` | Signal-processing module: one filter, `RiemannP300Classifier`. It scores every flash with the classifier `pipeline/fit_from_recording.py` fitted (xDAWN covariances → tangent space → shrinkage LDA), using the same epoching and zero-phase band-pass as training. The model arrives as a parameter file. See `CheckerboardSignalProcessing/RiemannP300Classifier.h`. |
| `parms/ThaiCheckerboard.prm` | Its parameter file: the matrix (from `collection/characters_th.json`), timing, and per-flash classifier settings. It is generated by `tools/make_bci2000_parms.py`; don't edit it by hand. |

## Build (once)

BCI2000 builds `src/custom` when it exists. Link this folder there, then configure and build:

```bash
ln -s "/Users/first/Desktop/BCI Research/P300 Speller/bci2000" ~/BCI2000/trunk/src/custom
cd ~/BCI2000/trunk/build
cmake .
make UnicornSerialSource CheckerboardSpeller CheckerboardSignalProcessing
```

The modules land in `~/BCI2000/trunk/prog/`. Rebuild with the same `make` line after any change here.

## Run

1. Pair the headset in System Settings → Bluetooth and switch it on. `/dev/cu.UN-<serial>` appears.
2. Open `~/BCI2000/trunk/prog/BCI2000Launcher.app`.
3. Pick **UnicornSerialSource**, a signal processing module and an application, then launch.
4. Leave `SerialPort` at `auto` when exactly one `/dev/cu.UN-*` port exists. Otherwise set it.

There's no headset in a test run. Instead:

1. Start `$PY tools/fake_unicorn_bt.py --port 9000`.
2. Set `TcpAddress` to `127.0.0.1:9000`.

The fake marks its data synthetic: all three gyroscope states read 0x5A5A, and the module warns.

## The speller

**Quick look, no headset:** `bci2000/demo_speller.sh [--slow] [TEXT]`. It starts the fake headset and BCI2000 and spells TEXT (default สวัสดีครับ) in copy mode. `--slow` makes each flash last 0.5 s so the lit cells can be inspected.

By hand:

1. Launch **UnicornSerialSource**, **P3SignalProcessing** and **CheckerboardSpeller**.
2. In Config, **Load** `bci2000/parms/ThaiCheckerboard.prm`.
3. For calibration, set `InterpretMode` to 2 (copy) and type the sentence into `TextToSpell`. Each character is cued in green before its flashes, and the run ends after the last one.
4. Free spelling (`InterpretMode` 1) needs a fitted classifier. That's the next port.

Timing is whole sample blocks. The parameter file sets 16 ms blocks and a 64 ms flash plus a 64 ms gap, the nearest to the paradigm's nominal 62 + 62 ms.

The recording carries everything the old marker stream did:
- `StimulusCode`: the flash number within the selection;
- `StimulusType`: whether the flash contains the cued character;
- `FlashChar1`–`FlashChar6`: the lit characters, 1-based;
- `AttendedChar`, `SelectedChar`.

Two settings matter for P3SignalProcessing. Each flash has its own stimulus code, so `EpochsToAverage` must be 1 **and** `SingleEpochMode` must be 1. Without `SingleEpochMode`, BCI2000's `P3TemporalFilter` counts a code's epochs across selections and silently returns nothing for every other selection. The parameter file sets both, and the module refuses to start otherwise.

**Still to check by eye:** Thai rendering in the speller window. BCI2000 draws text in Helvetica, and macOS substitutes a Thai font. Look at the tone and vowel marks before real use, including the lone combining marks in their own cells.

## Calibrate, fit, spell

1. **Calibration session.** Launch **UnicornSerialSource**, **DummySignalProcessing** and **CheckerboardSpeller**. Load `parms/ThaiCheckerboard.prm`, set `InterpretMode` 2 and `TextToSpell` to the calibration sentence, then run. BCI2000 writes `<DataDirectory>/<Subject><Session>/<Subject>S<session>R<run>.dat`.
2. **Fit** from that file:
   ```bash
   $PY -m pipeline.fit_from_recording --recording <path>.dat --id subject_001
   ```
   This writes the usual checkpoint, Platt calibration, manifest and fit report, plus `models/subject_001_bci2000.prm`, the model for BCI2000.
   - Flash onsets come from `StimulusCode`, labels from `StimulusType`, and each selection is one cross-validation group.
   - Epochs touching lost Bluetooth samples are rejected.
   - Fake-headset data is refused unless you pass `--allow-demo`.
3. **Online session.** Launch **UnicornSerialSource**, **CheckerboardSignalProcessing** and **CheckerboardSpeller**. Load `parms/ThaiCheckerboard.prm`, **then** `models/subject_001_bci2000.prm`, then run.
   - The filter refuses to start on a different montage, sampling rate, source-side filter, or an `EpochLength` shorter than its result latency.

**What isn't scored:** the filter rejects a flash, online and in every offline path alike, when:
- its window touches a lost or counter-break sample;
- it fails the quality gate (a flat or railed channel, `pipeline/quality.py`; `RiemannQualityGate` 0 turns the gate off);
- its channels are linearly dependent.

Rejected flashes appear in `ClassifierRejectedCode`. Each character's evidence is the mean of its scored flashes, so a rejection never biases a selection.

**How training and live use stay identical:** the online filter cuts each epoch from the same samples the offline fit uses. That's the padded window around the first sample of each `StimulusCode`, band-passed with zero phase on that window alone (scipy's `sosfiltfilt`). So a flash's live score equals the score you'd recompute from the recording.
- **Recorded per flash:** `ClassifierScore`, `ClassifierOnsetSample`, and `ClassifierRejectedCode` for unscored flashes.
- **Measured:** online scores equal offline recomputation within float32 storage rounding, and onsets are identical, on a full BCI2000 session (`tests/test_bci2000_classifier_e2e.py`).
- **The price:** each result arrives 1.3 s after its flash (0.8 s epoch plus 0.5 s filter padding), the same as the Python service. `EpochLength` is therefore 1400 ms, so the speller waits for every result before deciding.

## Lost Bluetooth packets

BCI2000's clock is the sample count, so a lost sample has to keep its slot. Otherwise everything after it lines up with the stimulus states too early.

- **Short gaps:** each lost sample becomes a copy of the last real one, with `Validation = 0`. Every real sample has `Validation = 1`. Exclude epochs that touch `Validation == 0` in analysis.
- **Long gaps:** a gap longer than `MaxGapFill` (default 250 samples, 1 s) stops the run instead of being filled.
- **Totals:** the operator log gets packets, samples lost, gaps, the longest gap and bytes discarded when acquisition stops.

## Tests

- `tests/test_bci2000_unicorn_protocol.py` compiles the protocol code alone. It requires the same output as the Python reference, `collection/unicorn_protocol.py`, on the same bytes.
- `tests/test_bci2000_checkerboard.py` checks that the C++ checkerboard gives the same groups as `flash_sequence.py` for the same shuffles, and that the parameter file is current.
- `tests/test_bci2000_checkerboard_speller.py` runs the speller in BCI2000 and checks the `.dat` flash by flash. It opens a window, so it runs only with `BCI2000_GUI_TESTS=1`.
- `tests/test_bci2000_riemann.py` checks that the C++ classifier arithmetic equals the fitted sklearn/pyriemann pipeline and its numpy specification within 1e-9.
- `tests/test_bci2000_classifier_e2e.py` runs calibrate → fit → online in BCI2000 and checks online against offline flash by flash. It opens a window, so it runs only with `BCI2000_GUI_TESTS=1`.
- `tests/test_bci2000_unicorn_source.py` runs BCI2000 against the fake headset and reads the `.dat` with BCI2000's own `BCI2000Tools.FileReader`. It skips when BCI2000 isn't built, and when another BCI2000 source module is running.
